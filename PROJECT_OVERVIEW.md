# NEONEXUS Project Overview

This document provides a comprehensive breakdown of the NEONEXUS NFT Marketplace project, detailing its purpose, architecture, directory structure, and the responsibilities of individual files.

---

## General Information & Architecture

**NEONEXUS** is an end-to-end, decentralized application (dApp) that allows users to explore, submit, trade, and auction ERC-721 non-fungible tokens (NFTs). The project demonstrates how to integrate modern Web3 technologies across a full stack.

The architecture is split into three main micro-components:
1. **Blockchain (`/blockchain`)**: The smart contracts that manage ownership, escrows, bidding logic, and direct sales. Built with Solidity and Hardhat.
2. **Backend Server (`/server`)**: A lightweight Express.js REST API that utilizes a JSON file (`db.json`) for persistence. It acts as an indexing service to keep track of deployed contract addresses and known NFTs so the frontend can query them without scanning the entire blockchain.
3. **Frontend UI (`/frontend`)**: A React + Vite single-page application (SPA). It uses `ethers.js` to communicate with the user's MetaMask wallet and the smart contracts, providing a sleek, glassmorphism-styled interface.

---

## Directory & File Structure

### Root Directory
The root directory acts as a workspace manager to control all three sub-projects concurrently.
* **`package.json`**: Contains global workspace scripts (e.g., `npm run dev`, `npm run node`, `npm run deploy`) that trigger commands in the respective sub-folders.
* **`README.md`**: Provides the step-by-step setup guide and basic troubleshooting instructions.
* **`PROJECT_OVERVIEW.md`**: (This file) Deep dive into the codebase architecture.

---

### 1. Blockchain (`/blockchain`)
Contains the local Ethereum development environment, smart contracts, and deployment scripts.

* **`/contracts/`**
  * **`NFTMarketplace.sol`**: The core logic of the marketplace. It handles listing NFTs for direct sale (`listNFT`, `buyNFT`) and creating time-bound auctions (`createAuction`, `bid`, `endAuction`).
  * **`SampleNFT.sol`**: A standard implementation of an ERC-721 token (inheriting from OpenZeppelin). It is used to mint test assets for the marketplace.
* **`/scripts/`**
  * **`deploy.js`**: A Hardhat script that compiles and deploys the smart contracts to the local network. Importantly, it automatically saves the deployed contract addresses to the backend database (`server/db.json`) and the ABIs to the frontend (`frontend/src/abi.json`).
  * **`samples.js`**: A seeding script that mints initial test NFTs, lists some for direct sale, puts some on auction, and records them in the database for immediate testing.
* **`hardhat.config.js`**: Configuration file for Hardhat, specifying the Solidity compiler version and local network settings.

---

### 2. Backend Server (`/server`)
A simple off-chain indexer to help the frontend discover NFTs efficiently.

* **`server.js`**: The Express.js application entry point. It sets up REST endpoints (like `GET /api/nfts`, `POST /api/nfts`, `GET /api/contracts`) and configures `cors` to allow the frontend to communicate with it.
* **`db.json`**: A JSON-based database managed by `lowdb`. It stores:
  * `contracts`: The deployed addresses of the `NFTMarketplace` and `SampleNFT`.
  * `nfts`: An array of objects representing discovered NFTs (storing their `contract` address and `tokenId`).

---

### 3. Frontend (`/frontend`)
The user interface, built with React and Vite, responsible for rendering data and prompting the user for MetaMask signatures.

* **`/public/` & `/src/assets/`**: Contains static assets like favicons, hero images, and sample NFT images used by the seed scripts.
* **`vite.config.js`**: The configuration file for the Vite bundler.
* **`/src/`**
  * **`App.jsx`**: The root React component. It sets up the `react-router-dom` routing and creates the `Web3Context`. It handles connecting to the user's MetaMask wallet and passing the Ethereum `provider` and `signer` down to the pages.
  * **`abi.json`**: Auto-generated by the deployment script. Contains the Application Binary Interfaces (ABIs) needed by `ethers.js` to call functions on the smart contracts.
  * **`utils.js`**: Contains reusable helper functions. Notably, `fetchNFTData` merges off-chain data from `db.json` with on-chain data (owner, token URI, sale status, auction bids) from the smart contracts.
  * **`index.css` & `App.css`**: Global stylesheets implementing the futuristic, neon-glassmorphism design aesthetic.

* **`/src/pages/`** (The main views of the application)
  * **`Welcome.jsx`**: The landing page introducing the marketplace with a call-to-action to explore.
  * **`Explore.jsx`**: Fetches all known NFTs from the backend, reads their on-chain state, and displays them in a responsive grid. Includes filters for "For Sale" and "On Auction".
  * **`NFTPage.jsx`**: The detailed view for a single NFT. This handles complex logic:
    * Displays metadata, current owner, and pricing/auction status.
    * Allows buyers to execute `buyNFT` or `bid`.
    * Allows the owner to list the NFT for sale.
    * Hides buy/bid buttons if the current user is the owner of the NFT.
  * **`Portfolio.jsx`**: Similar to the Explore page, but filters the NFT grid to exclusively show tokens owned by the currently connected MetaMask account.
  * **`Submit.jsx`**: A form that allows users to submit external ERC-721 contract addresses and token IDs to the backend API. This registers newly minted or custom NFTs into `db.json` so they become visible on the Explore page.
